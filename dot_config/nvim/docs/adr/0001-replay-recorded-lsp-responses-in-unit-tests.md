# Replay recorded LSP responses in layer A instead of running real servers for LSP-behavior tests

LSP-behavior tests move from layer B (real jdtls and kotlin-lsp, with index waits up to 180s) to layer A, which replays responses recorded from those servers on the fixtures under `tests/contracts/`. This trades some fidelity for speed and determinism: recordings can go stale when a server changes, so `mise run nvim:update` re-records them whenever a Mason pin moves. Recording runs the replayed tests against the real servers, so that is also where drift shows up; no scheduled run is needed, since the servers only change when a pin moves. Build, lifecycle and DAP tests stay on real servers because replay cannot cover them.
